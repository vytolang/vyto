# vyto/compress — DEFLATE, zlib and gzip

```vyto
import { gzip_compress, gunzip } from "vyto/compress";

let packed = gzip_compress(data);

let r = gunzip(packed);
if (!r.ok) { print(r.err); return; }
use(r.data);
```

Three framings of the same DEFLATE stream. They are **not interchangeable** — a
decoder has to be told which one it is reading, and reading gzip data as zlib
fails rather than producing nonsense:

| Framing | What it adds | Spec |
|---|---|---|
| `FMT_RAW` | nothing — bare DEFLATE | RFC 1951 |
| `FMT_ZLIB` | 2-byte header, Adler-32 trailer | RFC 1950 |
| `FMT_GZIP` | 10-byte header, CRC-32 + length trailer | RFC 1952 |

Backed by zlib 1.3.1, vendored and compiled from source on every build. No
`#link`, no provisioning step, no per-triple directory — the package
cross-compiles unchanged.

## API

| Function | Notes |
|---|---|
| `gzip_compress(src, level = 6)` · `gunzip(src, limit)` | |
| `zlib_compress` · `zlib_decompress` | |
| `deflate_raw` · `inflate_raw` | |
| `compress(src, format, level)` · `decompress(src, format, limit)` | the general form |
| `Deflater(format, level)` · `Inflater(format)` | streaming: `push()`, `finish()`, `ok()` |
| `compressAvailable()` | false only on `--freestanding` |
| `zlibVersion()` | the vendored version, `"1.3.1"` |

**Compressing returns `byte[]`; decompressing returns a `CompressResult` you
have to check.** That asymmetry is deliberate. Compression cannot fail on valid
input — every byte sequence has an encoding, so the only failures are
out-of-memory and a bad level, which are bugs in the caller. Decompression can
fail on *every* input, because the bytes are usually untrusted: they came off a
socket or out of a file someone else wrote. Same split as `vyto/crypto`'s
`AeadResult` and `vyto/crypto/ecc`'s `EccResult`.

**Every decompress entry point takes a `limit`,** defaulting to 256 MiB. A few
hundred bytes of gzip can expand to gigabytes; the limit is checked as the
output grows rather than after the fact, so it caps what is actually allocated.
Pass `0` only when the input is trusted.

**`finish()` is not a formality.** For decompression it is where the trailer is
verified, so a truncated stream is only detected there. A caller that stops
pushing and never finishes has checked nothing.

## Why zlib is vendored

The roadmap (`local/docs/MODULES.md:295`) called for `vytobind zlib.h --lib z` —
a binding against the system library. This package does not do that, for the
reason the tree has already recorded twice:

- **`vyto/regex`** reversed the same call (`MODULES.md:214`): *"'Drops a native
  dependency' dissolved once the dependency was vendored rather than fetched."*
- **`vyto/db`** vendored the SQLite amalgamation unprompted (`MODULES.md:299`),
  because *"a fetched dependency makes the suite skip silently, and for a
  database a green run that proved nothing is worse than a red one."*

`lib/vyto/regex/README.md` states the two criteria for the exception: the
dependency must be **pure C with no build system of its own**, and the module
must be **must-have**, so a fetched one would make tests silently skip. zlib
meets both more cleanly than PCRE2 did — 1.1 MB against PCRE2's 4.4 MB, and its
`configure` does nothing but flip two `#ifdef`s in `zconf.h`.

The system-library route would additionally have meant `zlib1g-dev` at build
time, a `provision-zlib.sh` for Windows (which has no system zlib), and a silent
skip on any machine without it.

## Layout

```
compress.vt                 the public API
native/
  refresh-zlib.sh           re-vendoring tool — not part of the build
  zlib.version / .sha256 / .files.sha256
  src/
    zlib_shim.c / .h        first-party, hand-maintained
    zlib_config.h           first-party build options
    vzlib_*.c               11 generated wrapper TUs
    zlib/                   pristine upstream, byte-identical
```

**Local changes go in `zlib_shim.c` or `zlib_config.h`, never in `src/zlib/`.**
The next refresh overwrites that tree, and `refresh-zlib.sh --verify` — which
`make test` runs — fails if it has been touched.

**The wrapper TUs are not optional.** `vytoc` globs `native/src/*.c` flat and
non-recursively (`src/main.c:1030-1046`), so `src/zlib/` is invisible to the
build; each upstream source needs a wrapper at the top level to be compiled at
all. One per TU, never a unity build: zlib has same-named file statics that
collide when translation units are merged. They are generated by the refresh
script rather than hand-maintained, so a source cannot be added without one.

**`zlib_config.h` is included by both the wrappers and the shim,** and that is
load-bearing: `Z_SOLO` changes which prototypes `zlib.h` declares, so a shim
compiled without it and a library compiled with it would disagree about the API.
The same trap `lib/vyto/db/sqlite/native/src/sqlite_config.h:1-12` records.

### Two things worth knowing about `Z_SOLO`

It drops the `gzopen`/`gzread` stdio file API, which this package does not use —
it works on byte buffers. That is why zlib's four `gz*.c` are not vendored, and
it keeps libc file I/O out of the dependency surface. It does **not** drop gzip
*framing*: that lives in `deflate.c` behind `GZIP`, not behind `Z_SOLO`.

It also removes zlib's own `zcalloc`/`zcfree`, so **a NULL `zalloc` is a hard
error rather than a request for the default** — `deflateInit2_` returns
`Z_STREAM_ERROR` (`deflate.c:393-396`). Every `z_stream` here is therefore
pointed at `zl_alloc`/`zl_free` in the shim. They wrap `malloc`/`free` rather
than the runtime's pool, because a package shim cannot reach `vt_host_alloc`:
it is `static` in hosted builds (`runtime/vyto_rt.c:61`) and this file has no
`-I` to `runtime/` regardless.

## Freestanding

zlib is built on an allocator, so there is nothing to degrade to. Under
`VT_NO_LIBC` the wrapper TUs compile to nothing and `zlib_shim.c`'s stub arm
answers with failure sentinels — the arrangement
`lib/vyto/db/sqlite/native/src/vsqlite3.c:16-23` uses. `compressAvailable()`
surfaces that, so `compress.vt` needs no platform conditional of its own.

Verified by `tests/fixtures/compress_freestanding.vt`, which exists to be
*built*, not run: the base freestanding test builds `01_hello.vt`, which imports
nothing, so nothing else would catch an unguarded include here.

## How this is tested

Three layers, and the distinction between the first two matters.

**Round-trip properties** — `tests/unit/compress_roundtrip.vt`, 69 assertions
against `vyto/dev/test`. Empty and one-byte inputs, incompressible data (where
the output is *larger* than the input — the direction buffer-sizing bugs assume
is impossible), NUL-heavy data, all ten levels, 40 seeded random round trips,
malformed input, bombs, and streaming against one-shot.

**Conformance** — `tests/fixtures/compress_conformance.vt`, driven from
`tests/run_tests.sh` against the **system gzip**. This is not redundant with the
above: those 69 assertions compare our encoder against our decoder, which share
an implementation. Fault injection confirmed the gap — changing the gzip
framing to zlib, so that what we call gzip is not gzip, left **68 of 69
round-trip assertions passing**. The conformance check failed immediately, in
both directions. Writing something `gunzip` can read proves the encoder; reading
what `gzip` wrote proves the decoder; a codec can fail either alone.

**Vendor integrity** — `refresh-zlib.sh --verify`, run by `make test`, fails if
`src/zlib/` has been edited. Fault-injected by appending a comment to
`adler32.c`; it failed as intended.

None of these can legitimately skip, which is the entire point of vendoring.
