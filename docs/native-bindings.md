# Generating native bindings with vytobind

`vytobind` turns a C header into a Vyto `extern "C"` module. It preprocesses
the header with the host compiler, parses the declarations with a best-effort
C subset parser, maps types onto Vyto's FFI surface, and prints a `.vt` module
on stdout. You redirect that output into a file and check it in — there is no
runtime step, no codegen at build time.

```sh
make                 # builds ./vytoc and ./vytobind
```

## Usage

```sh
./vytobind <header.h> [--lib name[@platform]]... [--filter prefix*]... [-I dir]... [--cc cc]
```

| Flag | Meaning |
|---|---|
| `--lib name` | emit `#link "name"` |
| `--lib name@platform` | emit `#link "name" if "platform"` — a conditional link, repeatable per platform |
| `--filter prefix*` | only emit symbols matching one of the given prefixes (glob-style, trailing `*` only); repeatable. Omit to emit everything the parser could map |
| `-I dir` | extra include path passed to the preprocessor |
| `--cc cc` | compiler to preprocess with (default `cc`) |

Output goes to stdout — redirect it:

```sh
./vytobind zlib.h --lib z --filter 'compress*' > zlib.vt
```

## Worked example

`examples/greeter/csrc/greeter.h`:

```c
#define GREETER_MAX_LEN 64
#define GREETER_MAGIC 0x2A

typedef enum { GREET_CASUAL, GREET_FORMAL = 5, GREET_LOUD } GreetStyle;

typedef struct GreetStats {
    int calls;
    double avg_len;
} GreetStats;

const char *greeter_hello(const char *name, int style);
long greeter_len(const char *s);
double greeter_scale(double x, float factor);
GreetStats greeter_stats(void);
void greeter_reset(void);

/* not representable in Vyto v0.1 — vytobind must skip these */
int greeter_printf(const char *fmt, ...);
void greeter_each(void (*cb)(const char *item));
```

Generated with:

```sh
./vytobind examples/greeter/csrc/greeter.h --filter greeter_* --filter GREET* > examples/greeter/greeter.vt
```

produces `examples/greeter/greeter.vt`:

```js
// Generated by vytobind from examples/greeter/csrc/greeter.h — do not edit.
// vytobind examples/greeter/csrc/greeter.h --filter greeter_* --filter GREET*

extern "C" {
    struct GreetStats { calls: i32; avg_len: f64; }
    fn greeter_hello(name: cstring, style: i32): cstring;
    fn greeter_len(s: cstring): clong;
    fn greeter_scale(x: f64, factor: f32): f64;
    fn greeter_stats(): GreetStats;
    fn greeter_reset();
    fn greeter_each(a0: rawptr);
}

const GREET_CASUAL: i64 = 0;
const GREET_FORMAL: i64 = 5;
const GREET_LOUD: i64 = 6;
const GREETER_MAGIC: i64 = 42;
const GREETER_MAX_LEN: i64 = 64;

// Skipped (not representable in Vyto v0.1):
//   greeter_printf — varargs
```

Note the header comment records the exact `vytobind` invocation used — keep
that line when you regenerate, so the next person can reproduce the output.

A bigger real one: `lib/vyto/surface/vsurf.vt` is generated from
`lib/vyto/surface/native/src/vsurf.h` with multiple platform-conditional
`--lib` flags:

```sh
./vytobind lib/vyto/surface/native/src/vsurf.h \
    --lib X11@linux --lib X11@macos --lib gdi32@windows --lib user32@windows \
    --filter vs_* --filter VS_* > lib/vyto/surface/vsurf.vt
```

## What gets mapped

| C type | Vyto type |
|---|---|
| `char *` / `const char *` | `cstring` |
| any other pointer, function pointer | `rawptr` |
| `_Bool` | `bool` |
| `char` / `signed char` | `i8`, `unsigned char` → `u8` |
| `short` / `unsigned short` | `i16` / `u16` |
| `int` / `unsigned int` | `i32` / `u32` |
| `long` / `unsigned long` | `clong` / `culong` (target-width: 64-bit on LP64, 32-bit on LLP64) |
| `long long` / `unsigned long long` | `i64` / `u64` |
| `float` / `double` | `f32` / `f64` |
| `enum` | `i32` (members become individual `i64` consts) |
| struct passed/returned by value | a mapped `struct { field: type; ... }`, only if every field is itself mappable |
| `#define NAME <int-literal>` | `const NAME: i64 = ...` |

Struct fields and function parameters that collide with a Vyto keyword (e.g. a
field named `len`) are renamed with a trailing `_` for fields, or `a0`, `a1`,
... for unnamed/keyword-colliding parameters.

A C function-pointer *parameter* (e.g. `void (*cb)(const char *item)`) still
maps — to `rawptr` — since the callback itself is fine to represent; only the
symbol being called doesn't need one. To actually pass a Vyto closure where the
binding wants that `rawptr`, wrap it with the `cthunk()` builtin, which
generates a matching C trampoline and prepends the closure as userdata (or
`cthunk_last()` to append it instead):

```js
// lib/vyto/net/http.vt — onChunk: fn(cstring, i32)
http_stream("GET".cstr(), url.cstr(), "".cstr(), "".cstr(), 0, 0,
            cthunk(onChunk), onChunk as rawptr)
```

## What gets skipped

Lossy by design. A declaration is dropped — and listed in a trailing
`// Skipped` comment with a reason — when it uses:

- **varargs** (`greeter_printf` above)
- **`long double`**
- **bitfields**
- **unions**
- **by-value structs with any unmappable field**
- names that collide with a **Vyto keyword**
- symbols with an `__asm__("...")` rename (the declared name isn't the real
  link symbol)

Skipped symbols are only listed if they also pass `--filter` — a filtered-out
symbol is silently omitted, not reported as skipped.

## After generating

The output is a normal `.vt` file — commit it, don't regenerate at build time.
If the header changes, rerun the same `vytobind` invocation (copy it from the
file's own header comment) and diff the result.

## Converting at the call site

`vytobind` only shapes the signature — it does not touch your call sites.
Every crossing is still an explicit conversion, the checker requires it:

| Direction | How |
|---|---|
| `int` → `i32` | `n as i32` — narrows, since Vyto `int` is 64-bit |
| `float` → `f64` | nothing; already exact |
| `string` → `cstring` | `s.cstr()` |
| `cstring` → `string` | `str(p)` — a builtin, not an import |
| `T[]` → `rawptr` | `xs as rawptr`, **plus** `xs.len as i32` as a separate argument |

```js
fn fillPolygon(xs: float[], ys: float[], rgb: int) {
    gfx_fill_polygon(this.handle, xs as rawptr, ys as rawptr,
                     xs.len as i32, rgb as i32);   // gfx/gfx.vt:156
}
```

See [`docs/types.md`](types.md) for the full type reference — value vs.
reference types, the fixed-width FFI family (§2), and `rawptr`/`cstring`
(§4).
